## Detailed Findings by Severity

### [P2] 可打印报告正文偏小

- **Location:** `web/app/globals.css:640`
- **Category:** Accessibility / Responsive
- **Impact:** 11px 正文在打印、PDF 和低视力场景中阅读成本偏高。
- **WCAG/Standard:** WCAG 1.4.4 Resize Text（相关可读性风险）。
- **Recommendation:** 将报告正文与列表提升至至少 12–14px，并在打印媒体中验证分页。
- **Suggested command:** `$impeccable typeset`

### [P2] 病例图片缺少统一加载优化

- **Location:** `web/app/page.tsx:228,250`、`web/app/cases/[id]/page.tsx:35`、`web/app/reports/[id]/page.tsx:21`、`web/app/review/page.tsx:375`
- **Category:** Performance
- **Impact:** 大病例图可能增加带宽和首屏解码开销；ESLint 共报告 5 个 `<img>` warning。
- **Recommendation:** 按 API 鉴权与打印约束选择 Next Image、自定义 loader，或至少为非首屏图片补充尺寸与延迟加载策略。
- **Suggested command:** `$impeccable optimize`

### [P2] 结果页两个 22px 入口抢占同等层级

- **Location:** `web/app/globals.css:535`
- **Category:** Implementation Integrity / Accessibility
- **Impact:** “查看病例详情”和“打开诊断报告”与区块标题接近同级，用户不易判断首要行动。
- **Recommendation:** 保留一个主要行动，另一个改为次级文字链接，并缩短结果后的纵向内容链。
- **Suggested command:** `$impeccable distill`

### [P3] 训练进度条动画 width

- **Location:** `web/app/globals.css:280`
- **Category:** Performance
- **Impact:** 更新进度时触发布局计算；只影响管理员训练监控。
- **Recommendation:** 改用 `transform: scaleX()`，并提供 `prefers-reduced-motion` 处理。
- **Suggested command:** `$impeccable animate`

### [P3] CPU 耗时提示使用单侧强调边框

- **Location:** `web/app/globals.css:508`
- **Category:** Implementation Integrity
- **Impact:** detector 将其识别为常见 side-tab 视觉反模式；当前仅一处状态提示，实际影响较低。
- **Recommendation:** 后续统一为现有完整边框 warning 样式或纯背景提示。
- **Suggested command:** `$impeccable polish`

### [P3] 次要链接触控高度略低于 44px

- **Location:** `web/app/components/PublicHeader.tsx` 品牌链接、首页历史预览链接
- **Category:** Accessibility / Responsive
- **Impact:** 390px 宽度实测高度分别为 40px 和 42px，手部操作不稳时点击容错略低。
- **WCAG/Standard:** WCAG 2.5.8 Target Size (Minimum)。
- **Recommendation:** 增加透明内边距或最小高度，不改变当前视觉密度。
- **Suggested command:** `$impeccable adapt`

### [P3] 颜色令牌覆盖不完整

- **Location:** `web/app/globals.css`
- **Category:** Theming
- **Impact:** 共享 CSS 中存在大量十六进制颜色，后续统一主题或调整对比度时维护成本高。
- **Recommendation:** 先抽取状态、图表和表面层令牌，不要求本轮引入暗色模式。
- **Suggested command:** `$impeccable colorize`

## Patterns & Systemic Issues

- 公共界面已经统一使用核心令牌，但旧首页、训练、复核、公共页面和 Admin 样式共存于一个 CSS 文件，后置覆盖容易造成字号和断点漂移。
- 图片加载策略分散在五个页面，没有统一的 API 图片组件或打印策略。

## Positive Findings

- 当前服务器、服务状态、缺项和分析阶段均有文字，不依赖颜色。
- 公共导航有视觉 active 状态和 `aria-current="page"`；桌面与移动都正确。
- 表单控件 5/5 有关联标签，图片 alt 完整，标题层级连续。
- 服务器与分析状态使用窄范围 polite live region；整个结果区不再频繁播报。
- 移动端底部导航、服务器标签和内容不重叠，页面无水平溢出。
- 后端接口为加法兼容修改，双服务器路由与病例归属逻辑未改变。
